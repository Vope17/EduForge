## 1. 為什麼重建

現有 EduForge 讓使用者填主題、對象就由 AI 生成教材。使用者的評價是：**下載後的產物嚴重不符預期**，而且沒有來源的內容不可信。具體問題與對應做法：

| 問題 | 重建後的做法 |
|---|---|
| 下載檔案和網頁預覽的版面差很多 | 預覽、Word、PDF 都由同一份區塊資料產生；PDF 由 Word 轉出（見 §8）。驗收要在 Word 與 PowerPoint 實際開啟 |
| 結構不像真正的教案、學習單、講義 | 每種產物有固定的必備結構，由後端檢查（見 §7） |
| 沒有來源，內容不可信 | 一律「先有來源，再有知識，才有產物」，產物附出處（見 §4–§7） |

做法是**以 Paper2Lab 為底，在 EduForge repo 的新分支改寫**，取代現有的前後端。Paper2Lab 已有的來源解析、知識版本、模板、產物編輯、版本紀錄與復原重做、AI 修改、模型連線都直接沿用。

Paper2Lab 起點：`/home/bcl/Projects/iLearn/Paper2Lab` 的 commit `6e07ffa`（main）。實作時在 `docs/` 記下實際複製的 commit。

## 2. 範圍

### 2.1 要做

1. 以**課程 → 章（資料夾）→ 節**組織，每一節依序有來源、知識、產物。
2. 來源接受 PDF、PPTX、DOCX。
3. 五種產物：教案、學習單、講義、課堂簡報（皆屬「節」），以及教學大綱與進度表（屬「課程」）。
4. 產物套用使用者匯入的 Word／PowerPoint 模板匯出；教案另內建表格式範本。
5. 繁體中文與英文介面；產物語言可獨立設定。
6. 保留名稱 EduForge、對外埠 8081。

### 2.2 不做

| 項目 | 原因 |
|---|---|
| 教學影片 | 使用者決定先不做。ChatGPT 訂閱沒有語音合成，之後再評估 |
| 沒有來源的生成 | 內容不可信，是重建的起因 |
| 重現實驗 C、SSH 執行器、Git 證據、已讀歷程 | 教學用不到。已讀歷程由課程順序取代（§9.2） |
| 跨篇比較章節 | Paper2Lab 的比較以多篇研究為單位，教學版不需要 |
| 國高中 108 課綱教案格式 | 教案採大學、研究所、讀書會、新人訓練適用的通用格式 |
| 搬舊資料 | 舊資料沒有來源，不符本規劃的原則；切換前請自行下載想留的檔案 |

### 2.3 之後再評估

- 教學影片（先做影片腳本，再合成無配音 MP4，最後才考慮語音）。
- 把 `docread` 做成共用容器，讓 Paper2Lab 與 Literature_Crew 也使用（§5.4）。
- 同一份來源供多節引用；跨章組合教材。
- 對應學校教務系統的欄位格式（教案以學校提供的表單替換內建範本即可）。

## 3. 領域模型

```text
課程 Course ── 設定預設值（對象、程度、每節時長、產物語言、模板）
 ├─ 教學大綱 Syllabus（課程層級產物）
 └─ 章 Chapter（資料夾，可排序、可覆寫設定）
     └─ 節 Lesson（可排序、可覆寫設定）
         ├─ 來源 Source（PDF／PPTX／DOCX）
         ├─ 知識 Knowledge（版本化，可編修）
         └─ 產物 Artifact：教案 ／ 學習單 ／ 講義 ／ 課堂簡報
```

對應 Paper2Lab：課程 ≈ 專案（Project），章 ≈ 資料夾（Folder），節 ≈ 研究（Paper）。Paper2Lab 的資料夾只有一層，這裡章也只有一層，不做巢狀章。

資料沿用 Paper2Lab 的 `Record`（`id`、`owner_user_id`、`kind`、`parent_id`、`version`、`data`）模式，kind 改為 `course`、`chapter`、`lesson`、`source`、`knowledge`、`artifact`、`task`、`template`。實作時依 Paper2Lab 的 `internal/domain` 與 `internal/store` 調整。

## 4. 來源

- 接受 PDF、PPTX、DOCX，沿用 Paper2Lab 的大小與頁數限制作為起點（單檔 300 頁），超過時回報明確錯誤。
- 每份來源解析成**頁單位 Unit**：`{id, source_id, locator, kind, text, preview, mode}`。`mode` 為 `text`（文字層）或 `vision`（影像辨識）。
- 出處格式沿用 Paper2Lab：`<來源id>:p<頁>`。PPTX 一張投影片為一頁；DOCX 以轉出 PDF 後的頁為準。
- 知識與產物裡每一項都能點回頁碼，並顯示原頁影像。

## 5. 文件解析套件 `docread`

### 5.1 介面

`internal/docread` 是獨立的 Go 套件，**不依賴 EduForge 其他程式**，之後才能被別的專案抽出使用：

```text
Read(ctx, path, options) → Document{ Title, Pages[]Page, Issues[] }
Page{ Index, Text, Image(PNG 路徑), Mode: text|vision, Issues[] }
```

### 5.2 各格式

| 格式 | 做法 |
|---|---|
| PDF | `pdftotext` 取文字（閱讀順序，避免雙欄交錯）、`pdftoppm` 轉頁面影像。沿用 Paper2Lab 的連字號、連字（ligature）修復 |
| PPTX | 先取投影片 XML 文字與備註，再用 LibreOffice 轉 PDF，轉成頁面影像，使模型看得到圖解與版面 |
| DOCX | 取段落、表格、標題層級文字，再用 LibreOffice 轉 PDF，轉成頁面影像 |

LibreOffice 轉檔沿用 Paper2Lab 的做法：每次獨立暫存目錄與 UserInstallation、參數陣列不經 shell、有逾時、成功與失敗都清暫存。

### 5.3 掃描頁

- 頁面抽不到足夠文字時，**不拒絕整份來源**，而是標成 `mode = vision`，讓模型直接看頁面影像辨識內容（這與 Paper2Lab 目前整份回 `ocr_required` 不同）。
- 影像辨識的段落在介面與產物的引用上標示「影像辨識」，提醒使用者核對。
- 只有在頁面影像也產生失敗時才回報錯誤。

### 5.4 每一頁都讀

Paper2Lab 的知識只附前 16 頁的影像。教材一章常有數十頁，因此改為參考 Literature_Crew 的 `pdf_reading.py`：

1. 依頁序分批（每批約 4 頁，受文字量與影像總位元組限制），每批附文字加頁面影像，由模型抽出該批的知識片段與頁碼。
2. 各批結果階層式彙整成一份知識，過程不遺漏任何頁。
3. 記錄**覆蓋率**（讀了幾頁、其中幾頁為影像辨識、哪些批失敗），顯示在介面上。覆蓋率不足 100% 時不能靜默視為完成。
4. 模型必須能讀影像（Codex、OpenAI API、Anthropic API）。只收文字的 Claude CLI 遇到影像來源時，介面要明確提示。

`docread` 只負責「檔案 → 每頁文字、影像、出處」。分批閱讀與彙整屬於知識層（§6），不放進 `docread`。

## 6. 知識

知識是來源與產物之間的唯一依據，版本化（沿用 Paper2Lab 的 Knowledge 版本與樂觀鎖），使用者可編修；產物記錄使用的知識版本。

**欄位**（每一項都有出處，沒有出處的項目不得寫入）：

| 欄位 | 說明 |
|---|---|
| 學習目標 | 此節學生學完要能做到什麼，動詞可評量 |
| 先備知識 | 此節假設學生已知的內容 |
| 核心概念與定義 | 概念名稱、定義、出處 |
| 公式 | 以 LaTeX 表示（沿用 Paper2Lab 的 `mathtex`），附符號說明 |
| 例題與解答 | 題目、解題步驟、答案、出處 |
| 常見迷思 | 迷思內容與更正 |
| 圖表 | 圖號、說明、所在頁 |
| 術語對照 | 原文用詞、中英對照、縮寫 |

規則：

- 以來源的原文用詞為主；來源沒寫的內容，查不到就留空，不補。
- 教學補充（例如 AI 自己想的例子）必須標示為「補充」，與來源內容區分。
- AI 可撰寫知識草稿，使用者審閱修改後才當作產物依據（沿用 Paper2Lab §15.7 的流程）。

## 7. 產物

所有產物都從知識生成，附出處，生成前套用本節的必備結構。結構不符時由後端檢查並回報，不靜默修正。

### 7.1 教案（節）

通用單元教案，**表格式**。必備內容：

1. 基本資料：單元名稱、設計者、教學對象、教學時間、教材來源（課程／章／節）
2. 教學研究：教材分析、學生經驗（取自先備知識）
3. 單元目標，以及分認知、情意、技能的具體目標，每個具體目標有代號
4. 教學活動表，欄位：目標代號、教學活動、時間、教學資源、評量方式；活動依序分準備活動、發展活動、綜合活動
5. 參考資料

後端檢查：各活動時間合計等於該節時長；每個具體目標至少對應一項活動；活動表引用的目標代號都存在。

### 7.2 學習單（節）

- 題型可混合：選擇、填空、簡答、計算、實作。題型配比與題數在生成設定裡選。
- 每題有：對應的學習目標代號、出處、配分。
- 輸出**學生版**與**教師版**兩個檔案。教師版附答案與解析。後端檢查：**學生版不得含答案或解析**（以測試保證，不靠提示詞）。

### 7.3 講義（節）

必備段落：本節重點、概念講解（含公式、符號說明、圖表）、例題與詳解、常見迷思、重點整理、課後練習（不附答案，答案在學習單教師版）。

深度分精簡、標準、深入三種，預設標準。篇幅區間先沿用 Paper2Lab 的設定，第 2 期以實際輸出調整後寫回本文。

### 7.4 課堂簡報（節）

沿用 Paper2Lab 的簡報 B：依知識順序、每個主題依時長寫成多張投影片、附講稿與時間估計、公式以 LaTeX、圖由 AI 依內容挑選、輸出可編輯的 PPTX。時長取自該節時長。

### 7.5 教學大綱與進度表（課程）

- 通用格式：課程基本資料、課程描述與目標、**每週進度**（週次、主題、對應章節、教學方式、作業與評量）、評分方式、教科書與參考書目。
- 依章與節的順序，以及各節的知識生成；週次由使用者設定總週數，AI 依各節份量分配，使用者可手動調整。
- 輸出 Word，並提供分欄的純文字，方便貼進學校的教務系統。

### 7.6 共通規則

- 產物生成前先顯示預覽，使用者確認後才進行完整生成（沿用 Paper2Lab 的 preview 任務）。
- 產物可編輯，有版本紀錄、復原重做、框選區塊後請 AI 修改（沿用 Paper2Lab 與已做好的 EduForge 編輯器行為）。
- 每份產物記錄：使用的知識版本、模型、輸出語言、設定與模板快照。

## 8. 模板與匯出

- 匯出**一律**套用使用者匯入的模板：Word（.docx／.dotx）用於教案、學習單、講義、教學大綱；PowerPoint（.pptx／.potx）用於課堂簡報。沿用 Paper2Lab 的模板匯入、母片分析、預覽。
- 預覽與下載共用同一份區塊資料。PDF 由匯出的 Word 轉出，保證版面與 Word 一致。
- **教案**用表格式範本：內建一份「通用單元教案」Word 範本，以**表格內的欄位標籤**（例如「單元名稱」「教學活動」）定位要填入的格子；使用者匯入學校的表單時，依相同標籤對應，不需改程式。找不到標籤時回報缺哪一個，不靜默略過。
- 學習單的學生版與教師版是兩個檔案，各自下載。
- 圖片、公式、字型沿用 Paper2Lab：公式轉為圖片或 Word 公式，內嵌 Noto Sans／Serif TC。

## 9. 設定與課程順序

### 9.1 設定的層級

課程設定預設值；章、節可覆寫，覆寫只影響該層以下。

| 設定 | 預設 |
|---|---|
| 教學對象 | 空（生成前必填） |
| 程度 | 大學 |
| 每節時長 | 50 分鐘 |
| 產物語言 | 跟隨介面語言，可各產物獨立設定 |
| 講義深度 | 標準 |
| Word／PowerPoint 模板 | 內建範本 |
| 使用者指示 | 每種產物各一欄，原文交給模型（內容仍只依來源） |

### 9.2 前面教過的內容

- 章與節可拖曳排序。
- 生成某一節的知識與產物時，同一課程中**排在它前面各節**的概念與術語列為「學生已學過」，可簡單提到、不重講；背景以概念名稱清單傳入，並有長度上限。
- 這取代 Paper2Lab 的手動「完成閱讀」。
- 產物與知識記錄生成當時的背景節清單。之後排序改變時，產物標示「背景已變動」，由使用者決定是否重新生成，不自動重生。

## 10. 模型連線

- 沿用 Paper2Lab 的 `providers`：Codex（ChatGPT 訂閱）、Claude Code、API Key，登入沿用官方流程。
- 現有 EduForge 的 `llm` 套件（含 `codex.go`）隨舊程式退役。
- 使用範圍維持單一使用者、使用者本人的帳號；README 保留「ChatGPT 訂閱僅供登入者本人使用」的說明。
- 驗收時教材內容會經 Codex 送到使用者的 ChatGPT 帳號處理，與平常使用相同。

## 11. 程式架構與改寫範圍

### 11.1 部署

沿用 Paper2Lab：**單一 Go 服務**同源提供 Vue 靜態檔與 API，不再有 Nginx 前端容器。對外埠 8081（`EDUFORGE_PORT`）。容器非 root、官方 CLI 與後端同容器、憑證放獨立 volume，沿用 Paper2Lab 的 `Dockerfile`、`compose.yaml` 與驗收腳本。

### 11.2 帶過來、改寫、不帶

| 帶過來（少量改名） | 改寫 | 不帶 |
|---|---|---|
| `internal/providers`、`internal/store`、`internal/httpapi`、`internal/mathtex`、`internal/style`（若仍需要）、前端編輯器與設計系統、`useUndo` | `internal/documents` → `internal/docread`；`internal/research` → `internal/knowledge`、`internal/generate`；`internal/artifacts` 的匯出與模板，新增教案、學習單、教學大綱；`internal/app`；前端的專案／研究頁改為課程／章／節 | `internal/experiments`、SSH、Git 證據、已讀歷程、跨篇比較、重現計畫 C |

### 11.3 EduForge 舊程式

- 舊的前後端在新分支移除，**保留在 git 歷史**（`main` 上的 `5843ddc` 為最後一版）。
- 舊功能裡要保留行為的：**框選後請 AI 修改**。Paper2Lab 目前只能點選多個章節或文字框（需求 §15.2），沒有文字範圍反白與拖曳框選。EduForge 現有的 `frontend/src/selection/useSelection.ts`（錨點含區塊、欄位、UTF-16 起訖，矩形框選）與後端 `/patches` 的錨點機制要移植進新版編輯器，在第 2 期完成，並維持現有測試涵蓋的行為。版本紀錄、復原重做 Paper2Lab 已有，直接沿用。
- 現有 EduForge 的產品需求（`AGENTS.md` §1）有兩項會改變，請審閱：
  - 「樣板確認閘門」：改為「匯入 Office 模板＋產物生成前預覽確認」。
  - 「風格偏好學習」：改為 Paper2Lab 的使用者指示與回饋（保存原文，可編修、停用、刪除、明確採用）。

### 11.4 型別與語言

沿用 Paper2Lab：前端 TypeScript strict，API 型別由 Go struct 產生（`make types`），`make test` 在型別過期時失敗。Go 版本以 `go.mod` 為準。

## 12. 分期

每期結束都 commit，且**讓使用者看過再進下一期**。第 1 到 3 期用合成教材驗收，第 4 期前使用者提供一章真實教材的路徑。

| 期 | 內容 | 完成條件 |
|---|---|---|
| 1 | **骨架、來源與知識**：複製 Paper2Lab、移除不帶的部分；課程／章／節結構、排序、設定覆寫；`docread`（PDF、PPTX、DOCX、掃描頁、頁面影像）；分批閱讀與覆蓋率；教學知識生成與編修；改寫 `AGENTS.md`、README | 三種來源都能解析並顯示頁影像；掃描頁以影像辨識進入知識；覆蓋率正確；知識每項有出處；`make test` 通過 |
| 2 | **講義與課堂簡報**：講義生成、編輯、Word／PDF 匯出；簡報生成、編輯、PPTX 匯出；模板套用；前面教過內容當背景；框選 AI 修改 | 兩種產物在 Word／PowerPoint 實際開啟，結構與版面符合預期；預覽與下載一致 |
| 3 | **教案、學習單、教學大綱**：三者的必備結構與後端檢查；教案表格範本與標籤對應；學習單雙版本；教學大綱與純文字輸出 | §13 的結構檢查全部有測試；教案時間檢查；學生版無答案 |
| 4 | **真實教材驗收與切換**：用真實一章走完整流程；在 Word／PowerPoint 實際檢查；18081 預覽通過後切換到 8081 | §13 全部通過；使用者確認 |

## 13. 驗收

### 13.1 自動測試

- 後端：`docread` 三種格式（含掃描頁、圖片、表格）；分批與覆蓋率；知識無出處不得寫入；教案時間合計與目標對應；學習單學生版不含答案；教案標籤對應與缺標籤回報；背景節清單與「背景已變動」；Paper2Lab 既有測試改名後仍通過。
- 前端：課程／章／節的建立、排序、覆寫；產物編輯、復原重做、版本還原；沿用現有 Vitest 與 vue-tsc、eslint。
- 模型呼叫以假 provider 測試，不在自動測試裡真的呼叫。

### 13.2 人工驗收（無法以程式取代）

1. 對每一種產物，下載 Word（簡報為 PPTX）與 PDF，**在 Word／PowerPoint 實際開啟**，核對：必備結構齊全、版面與預覽一致、中文字型正常、圖片與公式正常。
2. 教案的表格欄位與內建範本一致；換成另一份表格式範本後，標籤對應仍正確。
3. 從產物任一項出處點回原頁，內容確實出自該頁；影像辨識段落有標示。
4. 重啟容器後資料仍在；重新登入 ChatGPT 後可生成。
5. 同一份真實教材（含掃描頁與 PPT 圖解）能走完整流程，覆蓋率顯示合理。

## 15. 風險

| 風險 | 影響 | 對策 |
|---|---|---|
| 以 Paper2Lab 為底，兩套程式之後各自演進 | 修一個錯要改兩處 | 接受。`docread` 保持可獨立抽出，之後可共用 |
| 影像辨識錯誤（掃描頁、公式） | 知識有誤 | 標示「影像辨識」、覆蓋率可見、知識可編修、人工驗收含掃描頁 |
| 分批閱讀用掉大量 ChatGPT 訂閱額度 | 長教材可能撞到額度 | 顯示進度與預估批數；額度不足時保留已完成的批，之後續讀（沿用 Paper2Lab 的任務續跑） |
| LibreOffice 轉 PPTX／DOCX 的版面與 Office 不同 | 頁面影像與實際投影片有差異 | 影像僅供模型閱讀與出處對照，匯出不依賴它；人工驗收檢查 |
| 學校表單的表格結構特殊（合併儲存格、巢狀表格） | 標籤對應失敗 | 找不到標籤時回報，不靜默略過；表單差異大時再補對應規則 |
| 排序後「背景」改變 | 產物與新順序不一致 | 標示「背景已變動」，不自動重生 |
| 測試資料與真實教材差異 | 合成教材通過但真實失敗 | 第 4 期固定用真實教材；`docread` 測試納入掃描頁與多欄排版 |
