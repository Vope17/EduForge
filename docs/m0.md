# M0：網頁骨架

## 已確認的選擇

- HTTP：Go 標準庫 `net/http`，不引入第三方路由器。
- 部署：前後端各自使用 Docker，透過 Docker Compose 管理。
- 前端：Vue 3 Composition API、TypeScript strict、Vite、Pinia、vue-router、vue-i18n。
- 使用者：單一使用者、無登入。M0 不儲存使用者資料，也不呼叫生成服務。

```text
瀏覽器 http://localhost:8081
  └─ frontend:8080（正式：Nginx；開發：Vite）
       ├─ /                  Vue 應用程式
       └─ /api/* ────────── backend:8080（Go net/http）
```

正式前端保留原始 `/api/` 路徑轉送，不移除路徑前綴。開發環境的 `VITE_API_PROXY` 僅設定 Vite 伺服器的代理目標，不能放 API 金鑰。M0 沒有前端金鑰或後端服務憑證。

## API

### `GET /api/v1/health`

成功：HTTP 200，`Content-Type: application/json; charset=utf-8`，不快取。

```json
{"status":"ok","service":"eduforge"}
```

`HEAD` 支援相同狀態與回應標頭，不傳回 body。其他方法回傳 HTTP 405 與 `Allow: GET, HEAD`：

```json
{"error":{"code":"method_not_allowed","message":"Use GET or HEAD for this endpoint."}}
```

不存在的端點回傳 HTTP 404：

```json
{"error":{"code":"not_found","message":"Endpoint not found."}}
```

此端點只表示 HTTP 服務可用；尚未檢查資料庫或生成 provider。反向代理自身的連線失敗可能回傳 Nginx 的 502，前端一律顯示已翻譯的連線錯誤，不直接呈現回應內容。

## 介面與測試範圍

- 預設 `zh-TW`，切換至 `en` 時同步所有 UI 訊息、頁面標題與 `<html lang>`。重新整理後回到預設語言。
- UI locale 放在 Pinia，文案集中在兩份 JSON；測試比對兩語系的非空訊息鍵。
- 連線檢查讀取並驗證 health 回應，5 秒逾時，可手動重試；離開頁面會取消請求。
- Vitest 以 mock fetch 測試語言切換、錯誤後重試、逾時、離開頁面取消、錯誤狀態與回應格式。
- Go 測試驗證 health、HEAD、未知路徑、方法限制與一致錯誤 JSON。

首頁產物卡片與流程說明均標示為後續規劃。M0 沒有建立產物，因此還沒有產物語言設定、框選模組、revision、模板狀態機或資料庫；這些不變條件須在對應功能加入時一併測試，不以空的介面或假生成流程代替。

## 驗收

```bash
make config
make lint
make test
make build
make up
curl --fail http://localhost:8081/api/v1/health
```

最後用瀏覽器切換繁中／英文，確認連線成功、手機寬度正常顯示，並檢查 `docker compose ps` 兩個服務皆 healthy。開發環境另執行 `make dev`，修改 Vue 文案與 Go handler，確認同步更新與後端重啟。

執行期驗收需要可存取的 Docker daemon 與建置網路。Compose 設定解析通過後，仍須執行測試與瀏覽器驗收。
